1 · Who Who is this token for?

Determines the vocabulary the name must speak. A primitive is infrastructure — it doesn't need to communicate meaning. A semantic token must be legible to both designers and engineers.

Designers Engineers Both Internal alias only
2 · What What design decision does this token represent?

Describe the decision, not the value. What is this token not for? That negative boundary is often the most useful thing to document — it prevents misuse.

3 · Where Where is this token used?

Global tokens apply everywhere. Contextual tokens apply within a specific theme or mode. Component-scoped tokens only operate inside one component — consuming them elsewhere creates invisible coupling.

4 · When When does this token apply?

What state or condition activates this token? For stateless tokens (most primitives), document that explicitly — it tells the reader this token has no interaction dependency.

5 · Why Why was this name chosen over alternatives?

This is the question most often skipped and the one that pays off most over time. The reasoning you document today prevents the same debate from being relitigated by every future team member who encounters this name.

6 · How How does this token connect to adjacent tokens?

A token is a node in a network, not a standalone object. Documenting its connections makes the network visible — and makes the system navigable by anyone, including an LLM.
